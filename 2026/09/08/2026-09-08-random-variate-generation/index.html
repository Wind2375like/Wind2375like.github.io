4. Generating Random Variates

How to turn i.i.d. U(0,1) random numbers into observations from the distributions a model actually needs — the inverse transform and composition methods, and what makes a variate-generation algorithm good.

Goal. Study algorithms that produce observations (realizations) from some desired input distribution, given a stream of i.i.d. U(0,1)U(0,1)U(0,1) random numbers.

Chapter 3 produced the raw material: uniform random numbers. This chapter turns them into random variates from whatever distribution the model calls for — e.g. the exponential interarrival and service times of an M/M/1M/M/1M/M/1 queue.

4.1. Structure

  • It is essential to have a statistically reliable underlying RNG. Every algorithm below assumes its input really is i.i.d. U(0,1)U(0,1)U(0,1); a defective generator corrupts every variate built from it.

Factors in choosing an algorithm.

1. Exactness. An algorithm is exact if the variates it produces have exactly the desired distribution, not merely approximately.

Example of an inexact method. To generate Z∼N(0,1)Z \sim N(0,1)Z∼N(0,1):

  1. Generate u1,…,u12u_1, \dots, u_{12}u1​,…,u12​ i.i.d. U(0,1)U(0,1)U(0,1).
  2. Return Z=u1+u2+⋯+u12−6Z = u_1 + u_2 + \cdots + u_{12} - 6Z=u1​+u2​+⋯+u12​−6.

The moments come out right:

E[Z]=12⋅12−6=0,Var⁡(Z)=12⋅112=1,\mathbf{E}[Z] = 12 \cdot \tfrac{1}{2} - 6 = 0, \qquad \operatorname{Var}(Z) = 12 \cdot \tfrac{1}{12} = 1, E[Z]=12⋅21​−6=0,Var(Z)=12⋅121​=1,

and by the CLT the sum is approximately normal. But it is not exact. Since each ui∈[0,1]u_i \in [0,1]ui​∈[0,1], the output always satisfies

Z∈[−6,6],Z \in [-6, 6], Z∈[−6,6],

whereas a true N(0,1)N(0,1)N(0,1) variable has range (−∞,∞)(-\infty, \infty)(−∞,∞). The algorithm can never produce a value beyond ±6\pm 6±6, so it truncates both tails — exactly the region that matters most in reliability, risk, and rare-event studies. It is also wasteful: 12 random numbers per variate. Avoid it; use an exact method (§4.2.5) instead.

2. Efficiency.

  • memory usage;
  • execution time, including setup time (some algorithms precompute tables; that cost is paid once but must be counted).

3. Simplicity: easy to understand, implement, and debug. There is a trade-off between efficiency and simplicity — the fastest algorithm is rarely the clearest.

4. If possible, use exactly one random number per random variate. Reasons:

  • Simplicity.
  • Synchronization. When comparing two systems with common random numbers (§3.3, practical issue 3), we want the iii-th variate in system A to be built from the same uiu_iui​ as in system B. If one system consumes a variable number of uniforms per variate, the two streams drift out of step and the comparison loses its sharpness.
  • Monotonicity. With one uniform per variate and X=F−1(u)X = F^{-1}(u)X=F−1(u), the variate is a monotone function of uuu. This is what makes variance-reduction techniques such as antithetic variates work.

4.2. RVG Algorithms

Direct methods — build the variate straight from the definition of the distribution:

  1. Inverse transform — universally applicable in principle, but may be hard to implement.
  2. Composition ⎫
  3. Convolution ⎭ — apply only to input distributions of a specific form (mixtures and sums, respectively).

When these fail — that is, when F−1F^{-1}F−1 has no usable closed form and the distribution is neither a convenient mixture nor a convenient sum (the normal, gamma, and beta distributions are the standard examples) — fall back on:

  1. Acceptance–rejection method.
  2. Special techniques, e.g. for normal random variables.

4.2.1. Inverse Transform Method

Continuous case. Let XXX be a continuous r.v. with c.d.f. FFF.

Algorithm.

  1. Generate u∼U(0,1)u \sim U(0,1)u∼U(0,1).
  2. Return X=F−1(u)X = F^{-1}(u)X=F−1(u).

The catch is step 2: F−1F^{-1}F−1 must be computed, and for many distributions (normal, gamma, beta) it has no closed form.

Proof that the output has c.d.f. FFF.

P(X≤x)=P(F−1(u)≤x)=P(F(F−1(u))≤F(x))applying F to both sides; valid since F is non-decreasing=P(u≤F(x))=F(x)since u∼U(0,1).\begin{aligned} P(X \le x) &= P\left(F^{-1}(u) \le x\right) \\ &= P\left(F(F^{-1}(u)) \le F(x)\right) && \text{applying } F \text{ to both sides; valid since } F \text{ is non-decreasing} \\ &= P\left(u \le F(x)\right) \\ &= F(x) && \text{since } u \sim U(0,1). \end{aligned} P(X≤x)​=P(F−1(u)≤x)=P(F(F−1(u))≤F(x))=P(u≤F(x))=F(x)​​applying F to both sides; valid since F is non-decreasingsince u∼U(0,1).​

The last step is the definition of the uniform distribution: P(u≤a)=aP(u \le a) = aP(u≤a)=a for any a∈[0,1]a \in [0,1]a∈[0,1], and here a=F(x)a = F(x)a=F(x) is indeed in [0,1][0,1][0,1] because it is a probability. So the c.d.f. of the generated XXX is FFF, exactly — the method is exact.

Example: X∼Exp(λ)X \sim \text{Exp}(\lambda)X∼Exp(λ). Here F(x)=1−e−λxF(x) = 1 - e^{-\lambda x}F(x)=1−e−λx for x>0x > 0x>0. Set u=F(x)u = F(x)u=F(x) and solve:

u=1−e−λx  ⟹  e−λx=1−u  ⟹  x=−1λln⁡(1−u).u = 1 - e^{-\lambda x} \;\Longrightarrow\; e^{-\lambda x} = 1 - u \;\Longrightarrow\; x = -\frac{1}{\lambda}\ln(1 - u). u=1−e−λx⟹e−λx=1−u⟹x=−λ1​ln(1−u).

Algorithm.

  1. Generate u∼U(0,1)u \sim U(0,1)u∼U(0,1).
  2. Return X=−1λln⁡(1−u)X = -\dfrac{1}{\lambda}\ln(1-u)X=−λ1​ln(1−u).

Variant. Replace step 2 by “2′. Return X=−1λln⁡uX = -\dfrac{1}{\lambda}\ln uX=−λ1​lnu.”

This is valid because 1−u∼U(0,1)1 - u \sim U(0,1)1−u∼U(0,1) whenever u∼U(0,1)u \sim U(0,1)u∼U(0,1), so the two versions produce the same distribution. It saves one subtraction per variate — a genuine but small gain in a tight loop.

Two cautions, though:

  • Monotonicity is lost. Version 2 is increasing in uuu; version 2′ is decreasing. Under 2, a large uuu gives a long interarrival time in both of two systems being compared; under 2′ the correspondence is reversed. Where synchronization or antithetic variates matter, prefer 2.
  • The value u=0u = 0u=0. An LCG can output u=0u = 0u=0 (when zi=0z_i = 0zi​=0), and ln⁡0\ln 0ln0 is undefined. Version 2 never has this problem, since 1−u∈(0,1]1 - u \in (0, 1]1−u∈(0,1]. If 2′ is used, u=0u = 0u=0 must be screened out.

Efficiency problem. The number of comparisons the chain performs equals III, the index it returns. Since the algorithm returns xix_ixi​ exactly when I=iI = iI=i, and P(I=i)=P(X=xi)=p(xi)P(I = i) = P(X = x_i) = p(x_i)P(I=i)=P(X=xi​)=p(xi​), the number of comparisons NNN is a random variable with the same distribution as the index, so by the definition of expectation,

E[N]=∑i=1ni⋅P(N=i)=∑i=1ni p(xi).\mathbf{E}[N] = \sum_{i=1}^{n} i \cdot P(N = i) = \sum_{i=1}^{n} i\, p(x_i). E[N]=i=1∑n​i⋅P(N=i)=i=1∑n​ip(xi​).

If the probable values sit late in the list, this is close to nnn: tiny jumps at x1,x2,…x_1, x_2, \dotsx1​,x2​,… and the big jumps only at the end.

Two fixes.

  1. Binary search. Since F(x1)≤F(x2)≤⋯≤F(xn)F(x_1) \le F(x_2) \le \cdots \le F(x_n)F(x1​)≤F(x2​)≤⋯≤F(xn​) is a sorted array, locate uuu by bisection instead of scanning: O(log⁡2n)O(\log_2 n)O(log2​n) comparisons instead of O(n)O(n)O(n), whatever the probabilities.

  2. Reorder the comparisons. Test the values in decreasing order of probability. Relabel so that p(1)≥p(2)≥⋯≥p(n)p_{(1)} \ge p_{(2)} \ge \cdots \ge p_{(n)}p(1)​≥p(2)​≥⋯≥p(n)​ and build the cumulative sums for that new order; then E[N]=∑ii p(i)\mathbf{E}[N] = \sum_i i\, p_{(i)}E[N]=∑i​ip(i)​ is as small as possible. The reordering is done once in setup, so it costs nothing at run time.

Example. n=6n = 6n=6 with p=(0.05, 0.05, 0.10, 0.10, 0.20, 0.50)p = (0.05,\, 0.05,\, 0.10,\, 0.10,\, 0.20,\, 0.50)p=(0.05,0.05,0.10,0.10,0.20,0.50):

order of testing E[comparisons]\mathbf{E}[\text{comparisons}]E[comparisons]
as given: x1,x2,…,x6x_1, x_2, \dots, x_6x1​,x2​,…,x6​ ∑ii pi=4.85\sum_i i\,p_i = 4.85∑i​ipi​=4.85
decreasing probability: x6,x5,x3,x4,x1,x2x_6, x_5, x_3, x_4, x_1, x_2x6​,x5​,x3​,x4​,x1​,x2​ ∑ii p(i)=2.15\sum_i i\,p_{(i)} = 2.15∑i​ip(i)​=2.15

More than twice as fast, for no cost beyond sorting once.

Does reordering change the simulation? No. The output distribution is exactly the same — each xix_ixi​ is still returned with probability p(xi)p(x_i)p(xi​), because the intervals of (0,1](0,1](0,1] assigned to the values have the same widths p(xi)p(x_i)p(xi​); only their positions along (0,1](0,1](0,1] are permuted. The only thing that changes is the expected number of comparisons, i.e. the run time.

The one side effect: reordering destroys the monotone relationship between uuu and XXX, so the output is no longer F−1(u)F^{-1}(u)F−1(u) as a function of uuu. If synchronization or antithetic variates matter (see “Advantages” below), keep the natural order or use binary search, which preserves it.

Example: discrete uniform. X∼DU(1,100)X \sim DU(1,100)X∼DU(1,100), i.e. X∈{1,2,…,100}X \in \{1, 2, \dots, 100\}X∈{1,2,…,100} with p(i)=1100p(i) = \frac{1}{100}p(i)=1001​ for every iii, so F(i)=i100F(i) = \frac{i}{100}F(i)=100i​.

The general algorithm becomes:

  1. Generate u∼U(0,1)u \sim U(0,1)u∼U(0,1).
  2. if u ≤ 0.01 return X = 1; else if u ≤ 0.02 return X = 2; … ; else return X = 100

But here the chain can be replaced by a formula. The first iii with u≤i/100u \le i/100u≤i/100 is characterized by

i−1100<u≤i100⟺i−1<100u≤i⟺i=⌈100u⌉,\frac{i-1}{100} < u \le \frac{i}{100} \quad\Longleftrightarrow\quad i - 1 < 100u \le i \quad\Longleftrightarrow\quad i = \lceil 100u \rceil, 100i−1​<u≤100i​⟺i−1<100u≤i⟺i=⌈100u⌉,

so step 2 collapses to

  X=⌈100u⌉  \boxed{\;X = \lceil 100 u \rceil\;} X=⌈100u⌉​

— one multiplication and one ceiling, instead of up to 100 comparisons. (Equal probabilities are what make this possible; unequal ones need the search.)

Generalized inverse transform. To cover continuous, discrete, and mixed distributions in one statement:

  1. Generate u∼U(0,1)u \sim U(0,1)u∼U(0,1).
  2. Return X=min⁡{x:F(x)≥u}X = \min\{x : F(x) \ge u\}X=min{x:F(x)≥u}.

This is the same rule as before, written so it always makes sense. An ordinary inverse F−1F^{-1}F−1 requires FFF to be strictly increasing and continuous; a discrete FFF is flat in places (so no unique inverse) and jumps in places (so some values of uuu have no xxx with F(x)=uF(x) = uF(x)=u at all). Taking the smallest xxx whose F(x)F(x)F(x) has reached uuu handles both defects, and reduces to the usual F−1(u)F^{-1}(u)F−1(u) when FFF is continuous and strictly increasing.

Advantages and disadvantages of the inverse transform method.

Disadvantages.

  1. Must invert the c.d.f., which may have no closed form (normal, gamma, beta).
  2. May not be the most efficient approach even when the inverse exists.

Advantages.

  1. Easy to generate from truncated distributions. Truncating means restricting XXX to an interval [a,b][a,b][a,b] and renormalizing:

    F∗(x)=F(x)−F(a)F(b)−F(a),a≤x≤b,F^*(x) = \frac{F(x) - F(a)}{F(b) - F(a)}, \qquad a \le x \le b, F∗(x)=F(b)−F(a)F(x)−F(a)​,a≤x≤b,

    which is the original density chopped off outside [a,b][a,b][a,b] and scaled up so the area is again 1.

    Inverting F∗F^*F∗ costs nothing extra: generate u∼U(0,1)u \sim U(0,1)u∼U(0,1) and return

    X=F−1(F(a)+u [F(b)−F(a)]).X = F^{-1}\Big(F(a) + u\,\big[F(b) - F(a)\big]\Big). X=F−1(F(a)+u[F(b)−F(a)]).

    In words: instead of drawing uuu uniformly over all of (0,1)(0,1)(0,1), draw it uniformly over the slice (F(a),F(b))\big(F(a), F(b)\big)(F(a),F(b)) of the vertical axis. Every draw is usable — no rejection, one uniform per variate.

  2. Facilitates variance reduction when comparing alternative systems. Let X1∼F1X_1 \sim F_1X1​∼F1​ be the output of system 1 and X2∼F2X_2 \sim F_2X2​∼F2​ that of system 2, and suppose we want the difference in mean cost,

    E[X1]−E[X2]=E[X1−X2],\mathbf{E}[X_1] - \mathbf{E}[X_2] = \mathbf{E}[X_1 - X_2], E[X1​]−E[X2​]=E[X1​−X2​],

    so that X1−X2X_1 - X_2X1​−X2​ is an unbiased estimator of the gap. Generate both by inverse transform, X1=F1−1(u1)X_1 = F_1^{-1}(u_1)X1​=F1−1​(u1​) and X2=F2−1(u2)X_2 = F_2^{-1}(u_2)X2​=F2−1​(u2​). Since

    Var⁡(X1−X2)=Var⁡(X1)+Var⁡(X2)−2cov⁡(X1,X2),\operatorname{Var}(X_1 - X_2) = \operatorname{Var}(X_1) + \operatorname{Var}(X_2) - 2\operatorname{cov}(X_1, X_2), Var(X1​−X2​)=Var(X1​)+Var(X2​)−2cov(X1​,X2​),

    the precision of the comparison is controlled entirely by how we couple u1u_1u1​ and u2u_2u2​:

    coupling cov⁡(X1,X2)\operatorname{cov}(X_1, X_2)cov(X1​,X2​) Var⁡(X1−X2)\operatorname{Var}(X_1 - X_2)Var(X1​−X2​)
    1. u1⊥u2u_1 \perp u_2u1​⊥u2​ (independent) 000 Var⁡(X1)+Var⁡(X2)\operatorname{Var}(X_1) + \operatorname{Var}(X_2)Var(X1​)+Var(X2​)
    2. u1=u2u_1 = u_2u1​=u2​ (common random numbers) >0> 0>0 smaller
    3. u1=1−u2u_1 = 1 - u_2u1​=1−u2​ (antithetic) <0< 0<0 larger

    Case 2 is the useful one. Both F1−1F_1^{-1}F1−1​ and F2−1F_2^{-1}F2−1​ are non-decreasing, so a large uuu pushes both X1X_1X1​ and X2X_2X2​ up and a small uuu pushes both down: the two outputs move together, cov⁡(X1,X2)>0\operatorname{cov}(X_1,X_2) > 0cov(X1​,X2​)>0, and the variance of the difference drops. Note X1≠X2X_1 \ne X_2X1​=X2​ still, since F1≠F2F_1 \ne F_2F1​=F2​. Monotonicity is exactly what the inverse transform provides and what a rejection-based method does not — hence “facilitates”.

    (Case 3 is not useless in general; antithetic variates reduce variance when estimating a single mean by averaging X1X_1X1​ and X2X_2X2​, where the negative correlation helps. It is only harmful here, where we take a difference.)

4.2.2. Composition

The name. The target distribution is composed of simpler ones — the way a mixture’s chemical composition lists its ingredients. The method is also called the mixture method: decompose FFF into pieces you know how to sample from, pick a piece at random, then sample from it.

Setup. Use this when FFF can be written as a convex combination of other c.d.f.s F1,F2,…F_1, F_2, \dotsF1​,F2​,… (finitely or infinitely many):

F(x)=∑j≥1pjFj(x),∑j≥1pj=1,pj≥0.F(x) = \sum_{j \ge 1} p_j F_j(x), \qquad \sum_{j \ge 1} p_j = 1, \quad p_j \ge 0 . F(x)=j≥1∑​pj​Fj​(x),j≥1∑​pj​=1,pj​≥0.

Equivalently, in terms of densities or mass functions,

f(x)=∑j≥1pjfj(x)orp(x)=∑j≥1pj p(j)(x).f(x) = \sum_{j \ge 1} p_j f_j(x) \qquad\text{or}\qquad p(x) = \sum_{j \ge 1} p_j\, p^{(j)}(x). f(x)=j≥1∑​pj​fj​(x)orp(x)=j≥1∑​pj​p(j)(x).

  1. Generate a positive random integer JJJ with P(J=j)=pjP(J = j) = p_jP(J=j)=pj​ (a discrete variate — use the inverse transform of §4.2.1).
